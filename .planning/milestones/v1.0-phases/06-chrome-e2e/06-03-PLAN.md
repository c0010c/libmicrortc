# Phase 6 Plan 03: 真实 Chrome Host Transport 前置修复

<objective>
补齐 06-04 host Chrome E2E 所需的真实 host transport 能力：C answerer 必须给 Chrome 提供可连接的 host candidate，并让 Chrome 侧 `RTCPeerConnection.connectionState === "connected"`、DataChannel 真实 `ping:<nonce>` / `pong:<nonce>` 往返通过。该计划只解决连接和 DataChannel transport 前置条件，不实现浏览器媒体 stats / DOM / C on_frame 断言；这些继续由 06-04 负责。
</objective>

<discovery_context>
06-03 原计划执行时发现当前 C demo 会输出 C 内部 `pc.connected` 和 `datachannel.open`，但真实 Chrome 侧仍停在 `connecting`。关键观察：

- 默认 Playwright `MRTC_E2E_BROWSER_CHANNEL=chrome` 需要系统 Chrome；本机 `/opt/google/chrome/chrome` 不存在。
- `npm --prefix tests/e2e run install:browsers` 已能下载 bundled Chromium，但安装 Google Chrome 需要 sudo 密码。
- 使用 `MRTC_E2E_BROWSER_CHANNEL=chromium` 验证时，offer/answer 可交换，但 C answerer 发出的 candidate 为 `127.0.0.1 9 typ host`，不是可用 ICE/DTLS/SCTP endpoint。
- Chrome answer SDP 需要与 offer 的 m-line 顺序和 mid 保持一致；旧 answer 使用 `video0/audio0/data`，Chrome offer 使用 `0/1/2`。
- Browser 端错误事件不能回发给 C answerer，否则 C demo 将收到不支持的 message type 并提前退出。

本计划将这些发现转成可验证修复，避免 06-04 的 browser media 断言建立在假阳性的 C 内部状态上。
</discovery_context>

<must_haves>
<truths>
- Chrome 侧 `connectionState === "connected"` 是唯一连接成功门槛；C 侧内部事件只能作为诊断。
- DataChannel 成功必须由 browser 发 `ping:<nonce>`、C demo 回 `pong:<nonce>`，并由 browser 真实收到 pong。
- C answer SDP 必须保持 Chrome offer 的 m-line 顺序与 mid，不允许靠 browser 侧字符串改写兜底。
- Signaling server 只转发 schema 允许的 signaling/control 消息；browser diagnostic/error 不应写入 C demo stdin。
- 如果真实 ICE/DTLS/SCTP 行为仍缺底层协议能力，任务应在该层失败并输出明确 stage，而不是伪造 connected。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| C demo 内部状态被误当作 Chrome connected | HIGH | 新增 verifier/Playwright smoke 必须读取 browser `pc.connectionState` 和 DataChannel pong。 |
| SDP mid/m-line 不匹配导致 Chrome 拒绝 answer | HIGH | C answer 生成保留 remote offer mid/order，并用 browser smoke 覆盖。 |
| ICE candidate 不可达但测试继续执行 | HIGH | C answerer 必须暴露真实 host candidate endpoint；Chrome connection timeout stage 为 `connection`。 |
| Browser diagnostic 消息杀死 C demo | MEDIUM | Browser 端 diagnostic 不发给 signaling，server 过滤非 signaling/control schema。 |
</threat_model>
