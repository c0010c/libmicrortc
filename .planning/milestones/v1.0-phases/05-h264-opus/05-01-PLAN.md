# Phase 5 Plan 01: 媒体 Public API、Transceiver 与 SDP 合约

<objective>
建立 Phase 5 媒体路径的 public/private 合约：MRTC transceiver handle、H264/Opus codec 枚举、方向、`MRTC_FRAME`、frame/PLI callbacks、`mrtc_transceiver_write_frame()`，并让 SDP helper 根据 transceiver list 输出 H264/Opus 媒体 m-line。完成后，后续 RTP/RTCP 和 SRTP 媒体实现有稳定入口。
</objective>

<must_haves>
<truths>
- D-01/D-02: public API 保留 AWS 薄裁剪 transceiver/writeFrame/onFrame/onPictureLoss 模型，但只暴露 `MRTC_*` / `mrtc_*` 类型和函数。
- D-03: `MRTC_FRAME` 必须包含 data、size、presentation timestamp、decoding timestamp、duration、index、flags。
- D-04/D-05: 接收 frame 和 PLI 都通过 transceiver 级 callback 交给应用层。
- D-10/D-14: SDP 必须声明 H264 `packetization-mode=1;level-asymmetry-allowed=1;profile-level-id=42e01f`、`nack`/`nack pli`，以及 Opus `opus/48000/2` + `minptime=10;useinbandfec=1`。
- MEDIA-01/MEDIA-02: public API 不提供 capture、encoder、GStreamer、FFmpeg 或容器解析入口。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Public header 泄漏 AWS/PIC ABI 类型，破坏独立库边界 | HIGH | Header grep 排除 `PCHAR`、`PVOID`、`BOOL`、`UINT64`、裸 `STATUS` 等 token；只允许 `MRTC_STATUS`。 |
| API 命名或字段语义不足，后续 executor 无法表达编码后媒体帧 | HIGH | `MRTC_FRAME` 字段和 transceiver init/callbacks 在 public test 中逐项引用。 |
| SDP 仍停留在最小 first m-line echo，无法让 Chrome 看到 H264/Opus 能力 | HIGH | SDP tests assert exact `rtpmap`、`fmtp`、`rtcp-fb`、direction、mid lines。 |
</threat_model>
