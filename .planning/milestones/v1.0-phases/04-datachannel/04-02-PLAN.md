# Phase 4 Plan 02: Public API、ICE 配置与 SDP Transport 语义

<objective>
扩展 public PeerConnection API，使应用可以配置 STUN/TURN server、监听连接状态、创建和使用 DataChannel handle；同时扩展 SDP helper，使 answer 中包含 ICE credentials、DTLS fingerprint、`setup` role 和 SCTP/DataChannel m-line，并从 remote SDP 推导 DTLS 角色。
</objective>

<must_haves>
<truths>
- D-03: ICE server 配置通过项目根目录本地配置文件读取，测试直接加载 `urls`、`username`、`credential`。
- D-08: DTLS 角色必须从 SDP `setup` 属性推导，不通过测试配置硬指定。
- D-09: PeerConnection/SDP 流程需要生成自签名证书并写入 SDP `a=fingerprint`，DTLS 握手时校验远端 fingerprint。
- D-12/D-13: DataChannel public API 采用 AWS/WebRTC 薄裁剪风格，提供 handle、create、send、close 和 callbacks。
- D-14/D-15: Phase 4 支持 `negotiated=false` DCEP；消息支持文本和二进制。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Public API 泄漏 AWS/PIC 类型导致 ABI 污染 | HIGH | Public header grep 禁止 `PCHAR`、`PVOID`、AWS `STATUS`、`BOOL` 等 token。 |
| SDP answer 写入 fake fingerprint 或跳过远端 fingerprint | HIGH | SDP tests must assert `a=fingerprint:sha-256` is generated from DTLS cert wrapper and remote fingerprint parse result is stored. |
| DTLS role hardcoded | HIGH | Add tests for `actpass`、`active`、`passive` input and expected local role. |
</threat_model>
