# Phase 4 Plan 05: SCTP/DataChannel 与 Phase 4 验收收口

<objective>
在 DTLS application data 之上接入 usrsctp 和 DataChannel，支持 `negotiated=false` DCEP 打开流程、文本和二进制消息、关闭回调，并在真实 ICE/DTLS/SCTP 路径上验证 host、STUN 和 TURN relay DataChannel 行为。
</objective>

<must_haves>
<truths>
- D-12/D-13: DataChannel API 必须提供 handle、create、send、close、open/message/close callbacks。
- D-14: Phase 4 先支持 `negotiated=false` 的常规 DCEP 打开流程。
- D-15: DataChannel 消息支持文本和二进制。
- D-16: DataChannel 必须跑在真实 ICE/DTLS/SCTP 路径上验证。
- D-06: host、STUN srflx、TURN relay 都要进入 Phase 4 可运行验证范围。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| DataChannel 单元测试绕过真实 transport，Phase 4 虚假完成 | HIGH | Final verifier must require ICE selected pair, DTLS connected, SCTP association and DataChannel message over same path. |
| usrsctp global init/deinit 导致 flaky crash | MEDIUM | Add serialized global init wrapper and teardown tests. |
| DataChannel callbacks fire after handle free | HIGH | Ownership tests close/free channel and PeerConnection under pending callbacks. |
</threat_model>
