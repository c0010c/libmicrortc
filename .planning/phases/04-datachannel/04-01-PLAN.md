# Phase 4 Plan 01: 协议基础设施、依赖与测试骨架

<objective>
建立 Phase 4 协议迁入的私有基础设施：OpenSSL/libsrtp/usrsctp 依赖查找、C99 portability helpers、协议目录骨架、CTest/真实网络 harness 骨架和来源追溯规则。完成后，后续 ICE/DTLS/SRTP/SCTP 任务有统一的错误、内存、时间、socket、线程和验证入口。
</objective>

<must_haves>
<truths>
- D-01: Phase 4 必须有可运行 harness 验证真实连接路径。
- D-02: Phase 4 接受真实 STUN/TURN server 作为验收依赖。
- D-04: 真实 STUN/TURN 配置缺失或不可读时，真实网络验证必须失败。
- D-05: 计划和提交文档不得写入真实 TURN credential。
- BASE-01: 剥离基线必须是本地 `reflib/kvs-webrtc-sdk`。
- PROTO-01/02/03/05: ICE/STUN/TURN、DTLS、SRTP、SCTP/DataChannel 模块必须能进入核心库独立构建。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| AWS/KVS signaling、credential/storage 或 libwebsockets 被依赖链带入核心库 | HIGH | 每个迁入任务验证 `CMakeLists.txt include src tests` 中无 signaling/libwebsockets/AWSSDK/credential/storage 核心命中。 |
| OpenSSL/libsrtp/usrsctp 被 public headers 泄漏成安装消费者必须包含的 ABI | MEDIUM | 依赖只作为 `target_link_libraries(micrortc PRIVATE ...)`；public header grep 不出现第三方类型。 |
| 本地 TURN credential 被示例配置或计划文档提交 | HIGH | 只提交 `mrtc-ice-servers.example.json` placeholder；真实 `mrtc-ice-servers.local.json` 加入 `.gitignore`。 |
</threat_model>
