# Phase 4 Plan 03: ICE/STUN/TURN 候选与真实网络验证

<objective>
迁入或重写 ICE/STUN/TURN 核心，使 PeerConnection 可以生成 host、STUN server-reflexive 和 TURN relay candidate，并通过真实 harness 验证三种 candidate 路径。配置缺失必须失败，不能跳过。
</objective>

<must_haves>
<truths>
- D-01: 必须有可运行 harness 验证真实连接路径。
- D-02: 真实 STUN/TURN server 是 Phase 4 验收依赖。
- D-03: 测试从项目根目录配置文件读取 ICE server 字段。
- D-04: 配置缺失或不可读时真实网络验证必须失败。
- D-06: host、STUN srflx、TURN relay 都要进入可运行验证范围。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 真实网络验证在无配置时被 skip，造成假通过 | HIGH | `mrtc_phase4_network_verify` missing config test must exit non-zero and Phase 4 verification must run it. |
| TURN long-term credential 被日志打印 | HIGH | Harness redacts `username` and `credential`; tests assert output does not contain raw credential field value. |
| ICE accepts malformed remote candidates and corrupts state | MEDIUM | Candidate parser unit tests cover invalid foundation/component/protocol/type and return parse errors. |
</threat_model>
