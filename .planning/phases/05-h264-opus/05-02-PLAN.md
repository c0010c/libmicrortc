# Phase 5 Plan 02: RTP Packet 与 H264/Opus Codec Primitives

<objective>
实现可独立测试的 RTP packet parse/serialize、H264 Annex-B packetize/depacketize、Opus direct payload/depayload 和基础 RTCP packet helpers。完成后，PeerConnection 媒体发送/接收可以复用这些 primitives，而不是把 codec 行为写死在编排层。
</objective>

<must_haves>
<truths>
- D-06/D-07: H264 输入是 Annex-B bytestream，解析 `0x000001` / `0x00000001` start code，小 NALU Single NALU，大 NALU FU-A。
- D-09: H264 接收侧输出 Annex-B 重组帧。
- D-11/D-12/D-13: Opus 与 H264 共用 frame 模型，一个 Opus packet 对应一个 RTP payload，timestamp 使用 48kHz clock。
- D-17: RTCP helpers 至少覆盖 SR、RR、NACK、PLI 的 parse/generate 基础。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| H264 packetizer 只覆盖小 NALU，真实关键帧大包失败 | HIGH | Unit tests 必须覆盖 FU-A fragmentation 和 reassembly。 |
| H264 depay 输出不是 Annex-B，后续 fixture 写文件和验证困难 | HIGH | Tests assert output starts with `00 00 00 01` and contains reconstructed NALU bytes. |
| Opus timestamp 固定推断导致音频时序错误 | MEDIUM | Tests assert RTP timestamp comes from supplied presentation timestamp conversion。 |
| RTCP helpers 只解析 header，NACK/PLI 行为无法实施 | HIGH | Tests assert NACK PID/BLP list extraction and PLI target SSRC extraction。 |
</threat_model>
