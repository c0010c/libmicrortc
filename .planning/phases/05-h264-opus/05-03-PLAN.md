# Phase 5 Plan 03: SRTP 媒体发送/接收集成

<objective>
把 Plan 01 的 transceiver API 和 Plan 02 的 RTP/codec primitives 接入 PeerConnection 媒体发送和接收路径：`mrtc_transceiver_write_frame()` packetize 编码后 H264/Opus frame，生成 RTP，走 SRTP protect 后进入 transport send hook；接收路径 SRTP unprotect RTP 后 depay/reassembly，并调用 transceiver `on_frame`。
</objective>

<must_haves>
<truths>
- D-03/D-04: `MRTC_FRAME` 的 timestamp/index/flags 必须在发送和接收路径中保留到可观察回调。
- D-07/D-09/D-13: 发送侧 H264/Opus packetize，接收侧 H264 Annex-B 和 Opus packet 输出。
- D-12: Opus timestamp 使用 frame presentation timestamp 转 48kHz RTP clock。
- MEDIA-03/04/05/06: C 端发送和接收 H264/Opus 都要有可观察路径。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| `write_frame` 只调用 packetizer，不实际进入 SRTP/transport send | HIGH | Test asserts media send hook receives SRTP-protected RTP bytes and records packet count。 |
| 接收路径绕过 SRTP 或 codec depay，无法证明真实媒体 integration | HIGH | Test injects protected RTP, unprotects, depays, and observes `on_frame` callback。 |
| 多 transceiver SSRC/payload type 混淆 | HIGH | Tests create H264 and Opus transceivers and assert payload type/SSRC route to correct callback。 |
</threat_model>
