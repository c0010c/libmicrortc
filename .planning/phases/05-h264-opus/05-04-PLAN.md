# Phase 5 Plan 04: RTCP SR/RR、NACK 重传与 PLI 回调

<objective>
完成 Phase 5 要求的 RTCP 行为层：发送侧 RTP rolling buffer 保存可重发 packet，NACK 触发重发，PLI 触发 transceiver `on_picture_loss`，并支持 Sender Report / Receiver Report 的基础生成与解析。完成后，RTCP 不只是可解析字节，而能驱动媒体恢复行为。
</objective>

<must_haves>
<truths>
- D-05: PLI 必须触发应用层可响应的 `on_picture_loss` callback。
- D-17: RTCP 最小能力包含 Sender Report、Receiver Report、NACK 和 PLI，且只解析不驱动行为不足。
- D-18: NACK 使用发送侧 RTP rolling buffer + NACK 触发重发，按 RTP 层统一处理。
- PROTO-04: RTP/RTCP 模块支持基本 packetize/depacketize、RTCP 处理和 NACK 相关路径。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| NACK parser 有测试但重发路径没有行为 | HIGH | Test asserts retransmit send hook count and retransmitted sequence number。 |
| Rolling buffer 保存受保护包/未保护包策略不清导致重发失败 | HIGH | Store strategy documented in code comments and verified by NACK test after SRTP protect path。 |
| PLI callback 路由到错误 transceiver | MEDIUM | Test creates video and audio transceivers and asserts only video callback increments。 |
</threat_model>

<action>
Create `src/rtcp/rtp_rolling_buffer.h` and `src/rtcp/rtp_rolling_buffer.c`. Implement fixed-capacity storage keyed by RTP sequence number, with add, lookup, remove/overwrite, and free operations. Store enough bytes to retransmit the exact RTP packet expected by the media send hook according to the chosen strategy: if storing unprotected RTP, retransmit must re-run SRTP protect; if storing protected RTP, document and test that bytes can be resent directly.

<task id="05-04-02" type="execute">
<title>接入 NACK 解析与重发</title>
<read_first>
- `src/rtcp/rtcp_packet.*`

<action>
Create `src/rtcp/retransmitter.h` and `src/rtcp/retransmitter.c`. Wire protected inbound RTCP bytes through `mrtc_srtp_unprotect_rtcp()`, parse NACK PID/BLP sequence list, find the sender transceiver by media SSRC, retrieve packets from that transceiver rolling buffer, and send retransmit packets through the same media send hook used by Plan 03. Missing sequences must be counted or reported but must not crash or retransmit unrelated packets.
</action>
<verify>
<automated>`cmake --build build && ctest --test-dir build -R "nack|retransmit|rtcp" --output-on-failure`</automated>
</verify>
<acceptance_criteria>
- NACK test sends media packets with sequence numbers N, N+1, N+3, injects NACK for N and bitmask for N+1, and observes exactly two retransmit send hook calls.
- Unknown SSRC NACK returns deterministic status and does not invoke send hook.
- Missing sequence in rolling buffer increments a missing count or returns a nonfatal status visible to test.
</acceptance_criteria>
</task>

Do not implement REMB, TWCC, FIR, SLI, or congestion control in this task.

- PLI for unknown SSRC does not invoke callback and returns deterministic status.
- SR/RR test generates parseable packet types 200 and 201 and validates packet/octet count fields for at least one transceiver.
</acceptance_criteria>
</task>
