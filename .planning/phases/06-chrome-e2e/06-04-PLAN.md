# Phase 6 Plan 04: Chrome Host E2E 连接、DataChannel 与双向媒体断言

<objective>
实现默认 host/local Chrome E2E：Playwright 启动 browser 页面、signaling server 和 C answerer，完成 SDP/candidate 交换，断言 PeerConnection connected、DataChannel 双向 ping/pong、浏览器收到 C 端 H264/Opus、C 端收到 Chrome H264/Opus，并生成分阶段摘要。
</objective>

<must_haves>
<truths>
- D-05: Browser 视频成功必须结合 video element 可播放/有尺寸状态与 inbound RTP stats 增长。
- D-06: Browser 音频成功必须结合 audio stats 与 WebAudio/media playout 活动证据。
- D-07: C 侧媒体成功必须来自 `on_frame` 回调统计。
- D-08: 每路媒体用短时稳定阈值，不以一次事件通过。
- D-15: 输出至少区分 connection、DataChannel、browser media、C media 失败层。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 浏览器 E2E 只验证 connected，媒体没流动 | HIGH | `media-assertions.js` 对 video/audio/browser/C 四个方向分别检查 counters delta。 |
| H264 codec 在默认 Chromium 不可用导致误判核心库失败 | MEDIUM | Playwright config 支持 `MRTC_E2E_BROWSER_CHANNEL=chrome`，summary 报告 browser channel 和 codec stats。 |
| Flaky stats 采样造成偶发失败 | MEDIUM | 使用至少两次连续采样增长和明确 timeout/retry 参数。 |
</threat_model>
