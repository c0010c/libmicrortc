# Phase 6 Plan 01: E2E Tooling 与 Signaling Skeleton

<objective>
建立 Phase 6 的浏览器 E2E 工具骨架：`tests/e2e/` 中固定 Node/Playwright 依赖和 runner，`examples/chrome-e2e/` 中提供最小浏览器页面，使用本地 WebSocket signaling server 编排 Chrome offer、C answer、candidate 和状态事件，同时保持核心库 signaling-free。
</objective>

<must_haves>
<truths>
- D-01: WebSocket signaling server 是 demo/test 层资产，不修改 `micrortc` core target 的依赖边界。
- D-02: Runner 必须能启动 signaling server、C demo 子进程和 Playwright Chrome 页面。
- D-03: Browser 先创建 offer，C demo 返回 answer。
- D-04: `examples/chrome-e2e/` 与 `tests/e2e/` 分层明确。
- D-13/D-16: 默认 CTest 不依赖 Node/Playwright；Node 依赖只在 `tests/e2e/package.json`。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 应用层 signaling 泄漏进核心库 | HIGH | 所有 WebSocket/Node/stdio bridge 代码放在 `tests/e2e/` 和 `examples/`，`micrortc` target 不新增 signaling 依赖。 |
| E2E runner 输出混乱导致失败层不可定位 | MEDIUM | Runner 从第一版就输出 stage、event name 和 JSON summary。 |
| Playwright 依赖污染根工程 | MEDIUM | `package.json` 和 lockfile 只放在 `tests/e2e/`；README 使用 `npm --prefix tests/e2e`。 |
</threat_model>
