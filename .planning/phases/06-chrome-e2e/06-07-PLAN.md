# Phase 6 Plan 07: 真实 Chrome ICE/DTLS/SCTP Transport 缺口收口

<objective>
修复 06-03 执行后暴露的真实 Chrome transport 缺口：在 Chrome offer / C answer 主路径上接通可收包的 ICE/STUN host-lite packet path、OpenSSL DTLS 1.2 handshake、DTLS-SRTP key export 和 usrsctp/DCEP DataChannel，使严格 transport smoke 在浏览器侧达到 `RTCPeerConnection.connectionState === "connected"`，并完成真实 DataChannel `ping:<nonce>` / `pong:<nonce>` 往返。该计划完成后，06-04 才能继续实现浏览器媒体和 C 侧媒体断言。
</objective>

<gap_source>
本计划来自 `--gaps` 缺口收口。当前 Phase 06 目录没有 `06-VERIFICATION.md`，因此缺口来源采用已执行的 `.planning/phases/06-chrome-e2e/06-03-SUMMARY.md` 和 `.planning/debug/chrome-transport-smoke-blocks.md`：

- 06-03 已完成 SDP mid/order、真实 host candidate 端口和 browser diagnostic filtering。
- 严格命令 `MRTC_E2E_REQUIRE_TRANSPORT=1 MRTC_E2E_BROWSER_CHANNEL=chromium npm --prefix tests/e2e run test:host -- --grep "transport smoke"` 仍失败在 `connection` stage。
- 代码审计确认当前 `src/ice/ice_agent.c` 没有 UDP receive loop 和 STUN Binding success response，`src/dtls/dtls_session.c` 是 stub 级 fingerprint/keying wrapper，`src/sctp/sctp_session.c` 是 in-process callback wrapper。
- 06-04 的媒体断言不能建立在该 blocked transport 上。
</gap_source>

<must_haves>
<truths>
- Chrome 侧 `RTCPeerConnection.connectionState === "connected"` 是连接成功门槛；C 内部 `pc.connected` 只能作为诊断事件。
- DataChannel 成功必须由浏览器真实收到 `pong:<nonce>` 证明，不允许通过 C 内部 loopback callback 伪造。
- 本地 KVS 参考只能来自 `reflib/kvs-webrtc-sdk`，优先参考 `src/source/Ice/*`、`src/source/Stun/*`、`src/source/Crypto/Dtls_openssl.c`、`src/source/Sctp/*` 和 `src/source/PeerConnection/DataChannel.*`。
- 核心 `micrortc` target 可以链接 OpenSSL、libsrtp、usrsctp 等协议依赖，但不能引入 KVS signaling、AWS credential/storage、libwebsockets、GStreamer、FFmpeg 或媒体采集/编码。
- 严格 smoke 不允许 classification pass 代替真实通过；`MRTC_E2E_REQUIRE_TRANSPORT=1` 下必须对 `connection` 和 `datachannel` 失败返回非零。
</truths>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| Stub transport 继续把内部状态伪装成 Chrome connected | HIGH | `MRTC_E2E_REQUIRE_TRANSPORT=1` 只信 browser 本地 `pc.connectionState` 和 DataChannel pong。 |
| DTLS/SCTP 缺系统依赖时产生 passthrough 假阳性 | HIGH | 严格 transport 构建使用 `-DMRTC_REQUIRE_SYSTEM_TRANSPORT_DEPS=ON`，缺 OpenSSL/libsrtp/usrsctp 时 configure 非零失败。 |
| ICE 只发布 candidate 但不响应 Chrome connectivity check | HIGH | ICE task 必须实现 UDP 收包、STUN Binding request 校验和 Binding success response。 |
| 从 KVS 搬迁时引入 KVS signaling/AWS credential | HIGH | 只参考本地 `reflib/kvs-webrtc-sdk/src/source/{Ice,Stun,Crypto,Sctp,PeerConnection}` 的协议层；禁止纳入 `src/source/Signaling`、samples credential 和 libwebsockets。 |
| DataChannel open/message 仍由 loopback callback 触发 | HIGH | usrsctp/DCEP task 必须以 DTLS packet IO 驱动 OPEN/ACK/message，并用 browser pong 验收。 |
</threat_model>
