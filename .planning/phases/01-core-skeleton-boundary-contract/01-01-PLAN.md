# 计划 01：构建骨架、公共头入口与测试基础

<objective>
建立项目第一层可构建骨架：CMake 静态库目标、公共头文件导出、基础 `rtc_status_t`、纯 C 极小 test runner 和 CTest 接入。完成后，仓库应能在没有协议实现的情况下构建静态库并运行最小测试。
</objective>

<truths>
- 必须保持纯 C，不引入第三方测试框架或 GPL/LGPL 依赖。
- 公共 API 命名采用 `rtc_*` C 风格，语义接近浏览器 WebRTC。
- 首批目录按子系统提前分层，至少创建 `include/rtc`、`src/api`、`src/memory`、`src/executor`、`src/observability`、`tests`、`examples`、`cmake`。
- 所有 Markdown 文档必须使用中文；本计划不新增英文 Markdown 文档。
</truths>

<threat_model>
| 威胁 ID | 严重级别 | 场景 | 缓解 |
|---------|----------|------|------|
| T-01-01 | medium | 构建脚本引入第三方依赖或隐式下载，破坏宽松许可和嵌入式边界 | CMake 只创建本地静态库、测试和示例目标，不使用 FetchContent 或外部包 |
| T-01-02 | low | 公共头暴露不稳定内部布局，后续 ABI 难以维护 | 本计划只暴露状态码和聚合入口，不暴露 `PeerConnection` 内部结构 |
</threat_model>

  <title>创建 CMake 静态库骨架和目录结构</title>
  <read_first>

  <files>

    - `cmake/rtc_config.h.in`

  <action>
    创建顶层 `CMakeLists.txt`，设置 `cmake_minimum_required(VERSION 3.16)`、`project(rtc LANGUAGES C)`、`set(CMAKE_C_STANDARD 99)`、`set(CMAKE_C_STANDARD_REQUIRED ON)`。
    添加选项 `RTC_BUILD_TESTS` 和 `RTC_BUILD_EXAMPLES`，默认均为 `ON`。
    创建静态库目标 `rtc`，初始源文件为 `src/api/rtc.c`。
    设置 `target_include_directories(rtc PUBLIC include)`。
    创建目录 `include/rtc`、`src/api`、`src/memory`、`src/executor`、`src/observability`、`tests`、`examples`、`cmake`。
    创建 `cmake/rtc_config.h.in`，包含 `#define RTC_VERSION_MAJOR 0`、`#define RTC_VERSION_MINOR 1`、`#define RTC_VERSION_PATCH 0`。
  </action>
  <verify>

    - `test -d include/rtc && test -d src/api && test -d src/memory && test -d src/executor && test -d src/observability && test -d tests && test -d examples && test -d cmake`
    - `rg -n "add_library\\(rtc STATIC" CMakeLists.txt`

  </verify>
  <acceptance_criteria>

  <files>
    - `include/rtc/status.h`
    - `include/rtc/rtc.h`

    枚举必须包含：`RTC_STATUS_OK = 0`、`RTC_STATUS_INVALID_ARGUMENT`、`RTC_STATUS_INVALID_STATE`、`RTC_STATUS_UNSUPPORTED`、`RTC_STATUS_CAPACITY`、`RTC_STATUS_CAPACITY_ARENA`、`RTC_STATUS_CAPACITY_SDP_BUFFER`、`RTC_STATUS_CAPACITY_ICE_CANDIDATES`、`RTC_STATUS_CAPACITY_TIMER_SLOTS`、`RTC_STATUS_CAPACITY_PACKET_CACHE`、`RTC_STATUS_CAPACITY_TRACE_BUFFER`、`RTC_STATUS_AFFINITY_VIOLATION`、`RTC_STATUS_PROTOCOL_ERROR`、`RTC_STATUS_BACKEND_ERROR`。
    创建 `include/rtc/rtc.h`，包含 `status.h`，后续计划会继续加入 config、executor、observer、peer_connection 等公共头。
    `src/api/rtc.c` 至少包含 `#include "rtc/rtc.h"`，保证静态库有可编译源文件。
  </action>
  <verify>

    - `rg -n "RTC_STATUS_UNSUPPORTED|RTC_STATUS_AFFINITY_VIOLATION|RTC_STATUS_CAPACITY_TRACE_BUFFER" include/rtc/status.h`
    - `rg -n "#include \"rtc/status.h\"" include/rtc/rtc.h`
  </verify>
  <acceptance_criteria>

    - `include/rtc/rtc.h` contains `#include "rtc/status.h"`.
  </acceptance_criteria>
</task>
