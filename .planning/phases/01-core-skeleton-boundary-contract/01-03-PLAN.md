# 计划 03：执行器亲和、PeerConnection 生命周期与未支持 API 占位

<objective>
实现三执行器 vtable、执行器亲和检查、`PeerConnection` 不透明句柄、create/destroy 生命周期，以及后续 offer/answer/description/candidate API 的稳定占位。完成后，用户能用固定 arena 创建和销毁 `PeerConnection`，并能通过测试验证亲和契约。
</objective>

<truths>
- `rtc_peer_connection_t` 的真实布局不得出现在公共头。
- API 按职责分散到 `signaling`、`media`、`network` executor。
- UDP datagram 输入 API 必须在 `network` executor 调用。
- 未支持协议 API 应返回 `RTC_STATUS_UNSUPPORTED`，不能静默成功。
</truths>

<threat_model>
| 威胁 ID | 严重级别 | 场景 | 缓解 |
|---------|----------|------|------|
| T-03-01 | high | API 可从任意线程调用导致状态机竞态 | 执行器亲和检查在 release 返回 `RTC_STATUS_AFFINITY_VIOLATION`，debug 可断言 |
| T-03-02 | medium | 未实现 API 静默成功，后续阶段难以发现遗漏 | 所有占位 API 统一返回 `RTC_STATUS_UNSUPPORTED` 并计入后续可观测性 |
</threat_model>

- API-02：create 接收 `rtc_peer_connection_config_t`。
- API-03：所有公开 API 返回 `rtc_status_t`。
- API-05：每个函数亲和规则在测试和后续文档中可追踪。

- EXE-03：执行器可由用户映射到任意线程模型，库只依赖 vtable。
