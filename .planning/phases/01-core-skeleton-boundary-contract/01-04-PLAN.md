# 计划 04：observer、trace、计数器、文档与最小示例

<objective>
把生产可观测性和使用边界补齐为公共契约：细粒度 observer vtable、稳定 trace 事件名和字段键、计数器快照、结构化错误事件、最小 create/destroy 示例和中文执行器/内存文档。
</objective>

<truths>
- 可观测性是首版边界，不是后补日志。
- observer 按事件归属在 signaling、media 或 network executor 触发。
- trace 事件名和字段键从第 1 阶段开始稳定。
- 示例只做 create/destroy，不提前实现 Chrome 页面。
</truths>

<threat_model>
| 威胁 ID | 严重级别 | 场景 | 缓解 |
|---------|----------|------|------|
| T-04-01 | medium | 错误事件只给字符串，用户无法稳定自动化排障 | 错误事件包含 `rtc_status_t`、子系统、操作和 detail code |
| T-04-02 | medium | trace 字段后续随意变化，测试和生产排障失效 | 在公共头定义稳定 trace 事件名和字段键常量 |
| T-04-03 | low | 示例偷偷创建 socket 或线程，越过项目边界 | 示例仅演示 arena、executors、create/destroy，不做网络 I/O |
</threat_model>
