# 02-01 — SDP/JSEP 公共契约与固定内存骨架

<objective>
建立第 2 阶段所有后续计划共享的内部契约：create-time SDP 参数、固定 arena 切分、SDP/JSEP 内部类型、CMake/test stub 和 trace/detail 常量。完成后，后续 writer/parser/API 计划可以只填充实现，不再争抢公共接口。
</objective>

<context>
- 阶段上下文：`.planning/phases/02-sdp-jsep-offer-answer/02-CONTEXT.md`
- 研究：`.planning/phases/02-sdp-jsep-offer-answer/02-RESEARCH.md`
- 模式：`.planning/phases/02-sdp-jsep-offer-answer/02-PATTERNS.md`
- 第 1 阶段契约：`docs/API-执行器与内存契约.md`
</context>

<must_haves>
<truths>
- D-01: 只建立固定 Chrome 1v1 profile 的类型，不创建通用 SDP builder。
- D-02: ICE/DTLS 参数从用户 config 或测试夹具输入，本计划必须提供 create-time 参数入口。
- D-05: JSEP 状态只包含 `stable`、`have-local-offer`、`have-remote-offer`。
- D-10: candidate storage 必须受 `limits.ice.max_candidates` 控制。
- 固定内存: `rtc_peer_connection_create` 成功后不得依赖动态内存增长。
</truths>
<artifacts>
- `rtc_sdp_parameters_t` 或等价公开配置结构。
- `rtc_sdp_description_t`、`rtc_sdp_media_t`、`rtc_jsep_state_t` 等内部结构。
- `rtc_peer_connection_t` 中的 SDP/JSEP 固定存储字段。
- 新增 source/test 文件已接入 CMake。
</artifacts>
<key_links>
- `rtc_peer_connection_config_t` 持有 SDP 参数，`rtc_peer_connection_create` 校验并复制到 `rtc_peer_connection_t`。
- `src/sdp/sdp.h` 被 writer、parser 和 API glue 共享。
- `src/jsep/jsep.h` 被 API glue 和 `tests/test_jsep.c` 共享。
</key_links>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| SDP/candidate 存储运行期动态分配导致固定内存边界失效 | HIGH | 创建阶段按 `limits.sdp.max_description_bytes` 和 `limits.ice.max_candidates` 从 arena 切分，失败返回容量错误 |
| 公共 config 接受过长 ICE/DTLS 字符串 | MEDIUM | 明确字段容量常量，create 阶段长度校验，失败返回 `RTC_STATUS_INVALID_ARGUMENT` |
| trace 只有文本而无稳定 reason | MEDIUM | 在 `include/rtc/trace.h` 增加 signaling/sdp/jsep 字段与事件名 |
</threat_model>

<action>
扩展公开 create-time 配置和内部契约。具体目标：
1. 在 `include/rtc/config.h` 增加 `rtc_sdp_parameters_t` 并嵌入 `rtc_peer_connection_config_t`，字段至少包括 `const char *ice_ufrag`、`size_t ice_ufrag_len`、`const char *ice_pwd`、`size_t ice_pwd_len`、`const char *dtls_fingerprint`、`size_t dtls_fingerprint_len`、`const char *dtls_setup`、`size_t dtls_setup_len`、`uint64_t session_id`、`uint64_t session_version`。这些字段实现 D-02，不能生成随机数或证书。
2. 在 `include/rtc/trace.h` 增加事件名：`RTC_TRACE_SDP_PARSE`、`RTC_TRACE_SDP_WRITE`、`RTC_TRACE_JSEP_TRANSITION`、`RTC_TRACE_JSEP_REJECT`、`RTC_TRACE_ICE_CANDIDATE_STORED`；增加字段键：`RTC_TRACE_FIELD_STATE`、`RTC_TRACE_FIELD_TARGET_STATE`、`RTC_TRACE_FIELD_DESCRIPTION_TYPE`、`RTC_TRACE_FIELD_REASON`。
3. 创建 `src/sdp/sdp.h`，定义固定 Chrome 1v1 profile 内部类型：`rtc_sdp_type_t` (`RTC_SDP_TYPE_OFFER`, `RTC_SDP_TYPE_ANSWER`)、`rtc_sdp_direction_t` (`RTC_SDP_DIRECTION_SENDRECV`, `RTC_SDP_DIRECTION_RECVONLY`)、`rtc_sdp_media_kind_t` (`audio`, `video` 等枚举名可用 C 风格)、`rtc_sdp_description_t`，并声明 writer/parser 函数。结构必须显式包含 BUNDLE mids、ICE ufrag/pwd、fingerprint/setup、audio/video direction、Opus payload type、H264 payload type 和 `profile-level-id`。
4. 创建 `src/jsep/jsep.h`，定义 `rtc_jsep_state_t` 三态和用于校验 `createOffer`、`createAnswer`、`setLocalDescription`、`setRemoteDescription` 的函数声明。
</action>
