# 02-03 — Chrome SDP parser、profile validator 与错误路径

<objective>
实现长度有界 SDP parser 和 Chrome 1v1 profile validator，解析 Chrome offer/answer 中的 BUNDLE、rtcp-mux、ICE 参数、DTLS fingerprint/setup、Opus、H264 和媒体方向，并对结构错误、不支持字段和容量超限返回稳定错误。
</objective>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 输入 SDP 超长或无 NUL 导致越界读取 | HIGH | parser 只使用 `(const char *, size_t)`，禁止 `strlen` 读取未界定输入 |
| malformed line 被宽松接受并推进 JSEP 状态 | HIGH | parser/profile validator 返回错误，API 层不得状态转换 |
| Chrome fixture 中非目标 codec 污染支持范围 | MEDIUM | 允许跳过非目标 codec，但必须验证 Opus 111 和 H264 103/兼容 H264 存在 |
</threat_model>

<action>
实现长度有界 line scanner 和 profile validator。具体目标：
1. parser 函数签名必须接收 `const char *sdp` 和 `size_t sdp_len`；所有扫描循环以 `sdp_len` 为边界，不能依赖输入 NUL 终止。
2. 识别 session-level `a=group:BUNDLE 0 1`，并要求 audio `a=mid:0`、video `a=mid:1`。
3. 对每个 m-section 识别 `a=ice-ufrag:`、`a=ice-pwd:`、`a=fingerprint:`、`a=setup:`、`a=rtcp-mux`、direction。
4. audio validator 要求存在 `a=rtpmap:111 opus/48000/2`。
5. video validator 要求存在 H264 rtpmap 和 `packetization-mode=1`、`profile-level-id=42001f` 或等价 baseline profile；忽略 VP8/VP9/AV1/H265/RTX/RED/ULPFEC 等非目标 codec，但不得把它们标记为支持。
6. 返回码规则：结构缺失或格式损坏返回 `RTC_STATUS_PROTOCOL_ERROR`；`sendonly`/`inactive` 和无目标 codec 返回 `RTC_STATUS_UNSUPPORTED`；输入长度超过 `limits.sdp.max_description_bytes` 的检查由 API 层执行，但 parser 测试仍覆盖显式 oversized helper。
</action>
