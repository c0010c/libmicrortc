# 02-02 — 固定 Chrome 1v1 SDP writer 与 golden 输出

<objective>
实现固定 Chrome 1v1 SDP offer/answer serializer，使 `createOffer` 和 `createAnswer` 后续可以输出包含 BUNDLE、rtcp-mux、trickle capability、ICE 参数、DTLS fingerprint/setup、Opus、H264、`sendrecv`/`recvonly` 的 CRLF SDP。
</objective>

<context>
- 依赖计划：`02-01-PLAN.md`
- 研究：`.planning/phases/02-sdp-jsep-offer-answer/02-RESEARCH.md`
- RFC 引用：RFC 8866、RFC 8843、RFC 8839、RFC 6184
</context>

<must_haves>
<truths>
- D-01: 使用固定 Chrome 1v1 SDP 模板，不做通用 SDP builder。
- D-02: ICE/DTLS 参数来自 `rtc_sdp_parameters_t`，writer 不生成随机值或证书。
- D-03: 固定 Opus + H264 baseline profile，并用 golden tests 锁定 `rtpmap`、`fmtp`、`rtcp-fb` 和 payload type。
- D-04: writer 只输出 `sendrecv` 或 `recvonly`。
- D-13: writer 不依赖本机网络接口、socket、UDP 端口或平台网络枚举。
- D-15: session id、ICE ufrag/pwd 和 DTLS fingerprint 等动态字段必须使用测试夹具固定值，让 golden 比较可重复。
</truths>
<artifacts>
- `rtc_sdp_write_offer` 或等价函数。
- `rtc_sdp_write_answer` 或等价函数。
- `expected-local-offer.sdp` 和 `expected-local-answer.sdp` golden fixture。
</artifacts>
<key_links>
- `src/sdp/sdp_writer.c` 只消费 `src/sdp/sdp.h` 中的 profile description 和 config 参数。
- `tests/test_sdp_writer.c` 比较完整 golden 内容，并覆盖 buffer 过小错误。
</key_links>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 输出 SDP 超过调用方 buffer 导致写越界 | HIGH | 先计算 required length；不足时只写 `*inout_sdp_len` 并返回 `RTC_STATUS_CAPACITY_SDP_BUFFER` |
| 缺失 fingerprint/ICE 字段仍生成 SDP | HIGH | writer 对必填字段做长度检查，失败返回 `RTC_STATUS_INVALID_ARGUMENT` |
| 意外输出本地 candidate 造成第 3 阶段范围泄漏 | MEDIUM | golden fixture 断言没有 `a=candidate:` 行 |
</threat_model>

<action>
实现长度安全的固定 SDP writer。具体目标：
1. 在 `src/sdp/sdp_writer.c` 实现内部 append helper，所有写入都检查剩余容量；required length 使用同一条代码路径统计，保证 `RTC_STATUS_CAPACITY_SDP_BUFFER` 时 `*inout_sdp_len` 等于完整 SDP 所需字节数（不含或含 NUL 必须在函数注释和测试中固定）。
2. 实现 offer writer，输出 session-level：`v=0`、`o=- {session_id} {session_version} IN IP4 127.0.0.1`、`s=-`、`t=0 0`、`a=group:BUNDLE 0 1`、`a=msid-semantic: WMS *`。
3. 输出 audio m-section：`m=audio 9 UDP/TLS/RTP/SAVPF 111`、`c=IN IP4 0.0.0.0`、`a=rtcp:9 IN IP4 0.0.0.0`、ICE/DTLS 字段、`a=mid:0`、direction、`a=rtcp-mux`、`a=rtpmap:111 opus/48000/2`、`a=fmtp:111 minptime=10;useinbandfec=1`。
4. 输出 video m-section：`m=video 9 UDP/TLS/RTP/SAVPF 103`、`c=IN IP4 0.0.0.0`、`a=rtcp:9 IN IP4 0.0.0.0`、ICE/DTLS 字段、`a=mid:1`、direction、`a=rtcp-mux`、`a=rtpmap:103 H264/90000`、`a=rtcp-fb:103 nack pli`、`a=fmtp:103 level-asymmetry-allowed=1;packetization-mode=1;profile-level-id=42001f`。
5. 实现 answer writer，复用固定 profile，DTLS setup 输出 `active` 或从 config/test fixture 提供的 answer role，且不输出本地 candidate。
</action>
