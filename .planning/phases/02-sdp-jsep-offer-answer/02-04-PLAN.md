# 02-04 — Offer/Answer API、JSEP 状态机与 candidate 保存

<objective>
把 SDP writer/parser 接入现有 `PeerConnection` 公共 API，完成发起和接听流程、非法状态拒绝、远端 candidate 解析保存、observer/trace/counter 输出，并更新中文 API 契约文档。
</objective>

<context>
- 依赖计划：`02-02-PLAN.md`、`02-03-PLAN.md`
- 现有 API：`include/rtc/peer_connection.h`
- 可观测性模式：`src/api/peer_connection.c`、`tests/test_observability.c`
</context>

<must_haves>
<truths>
- D-05: 状态只包含 `stable`、`have-local-offer`、`have-remote-offer`。
- D-06: 发起流程必须是 `stable -> createOffer -> setLocalDescription(offer) -> have-local-offer -> setRemoteDescription(answer) -> stable`。
- D-07: 接听流程必须是 `stable -> setRemoteDescription(offer) -> have-remote-offer -> createAnswer -> setLocalDescription(answer) -> stable`。
- D-08: rollback、pranswer、renegotiation 和多轮协商必须被拒绝。
- D-09: 非法状态转换返回稳定 `rtc_status_t`，并输出 observer error 和 trace detail。
- D-10: `addIceCandidate` 解析、校验并保存远端 candidate 字符串，受 `limits.ice.max_candidates` 约束。
- D-11: `addIceCandidate` 不启动 ICE connectivity checks、candidate pair、STUN 或 priority 计算。
- D-12: 不触发 `on_local_candidate`。
</truths>
<artifacts>
- `rtc_peer_connection_create_offer` 和 `rtc_peer_connection_create_answer` 返回真实 SDP。
- `setLocalDescription` / `setRemoteDescription` 推进 JSEP 状态并保存 description。
- `addIceCandidate` 保存远端 candidate。
- 中文 API 文档更新第 2 阶段语义。
</artifacts>
<key_links>
- API glue 调用 `src/jsep/jsep.c` 做状态校验，调用 `src/sdp` 做 parse/write。
- observer/trace/counter 与第 1 阶段模式一致。
- docs 反映本阶段仍不执行 ICE/DTLS/RTP。
</key_links>
</must_haves>

<threat_model>
| Threat | Severity | Mitigation |
|--------|----------|------------|
| 非法状态转换仍保存 description | HIGH | 先 JSEP 校验，再 parse/write/保存；失败路径不修改 state 或 stored description |
| `addIceCandidate` 保存调用方指针导致悬挂引用 | HIGH | 复制 candidate 字符串到 arena 固定槽 |
| candidate 超限后覆盖已有候选 | MEDIUM | 达到 `limits.ice.max_candidates` 返回 `RTC_STATUS_CAPACITY_ICE_CANDIDATES`，candidate count 不变 |
| 第 2 阶段误触发本地 candidate observer | MEDIUM | 测试 observer 统计 `on_local_candidate` 调用次数必须为 0 |
</threat_model>

<action>
实现最小 JSEP 状态机和 API description 流程。具体目标：
1. 在 `src/jsep/jsep.c` 实现 create/set 校验函数：`createOffer` 仅允许 `stable`；`createAnswer` 仅允许 `have-remote-offer`；`setLocalDescription(offer)` 仅允许 `stable` 并转 `have-local-offer`；`setRemoteDescription(answer)` 仅允许 `have-local-offer` 并转 `stable`；`setRemoteDescription(offer)` 仅允许 `stable` 并转 `have-remote-offer`；`setLocalDescription(answer)` 仅允许 `have-remote-offer` 并转 `stable`。
2. 在 `src/api/peer_connection.c` 替换 `create_offer`、`create_answer`、`set_local_description`、`set_remote_description` 的 unsupported 返回：保持 signaling executor 亲和；调用 writer/parser；检查 `limits.sdp.max_description_bytes`；保存 local/remote SDP 字符串和 summary；成功时 trace `RTC_TRACE_JSEP_TRANSITION`，失败时 observer error + trace `RTC_TRACE_JSEP_REJECT`。
3. 非法顺序返回 `RTC_STATUS_INVALID_STATE`；不支持 direction/codec 返回 `RTC_STATUS_UNSUPPORTED`；缺失 BUNDLE/rtcp-mux/ICE/DTLS 字段返回 `RTC_STATUS_PROTOCOL_ERROR`。
4. 在 `tests/test_jsep.c` 覆盖发起流程和接听流程，断言最终状态回到 stable；覆盖 `createAnswer` 在 stable 直接调用返回 `RTC_STATUS_INVALID_STATE`；覆盖 answer 在没有 local offer 时 `setRemoteDescription` 返回 `RTC_STATUS_INVALID_STATE`。
</action>
