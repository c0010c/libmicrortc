## ID 21-23 实施计划：Pump 接口 + 有界事件队列 + 背压语义

### Summary
- 目标是完成 `id=21~23`，且保持“外部 pump 驱动、无后台线程、固定内存上界”。
- 路线已锁定为最小改动方案：补齐 `webrtc_pump` 头文件、实现内部固定容量队列、队列满返回专用错误码。
- 与参考库差异是有意为之：参考库偏内部 timer/线程与动态队列；本项目按 `<3MiB` 与 RTOS 友好目标采用外部 pump + 显式背压。

### Key Changes
- 公共接口调整：
  - 新增 [webrtc_pump.h](/home/qshl/dev/rtc/s2/include/webrtc/webrtc_pump.h)，声明 `webrtc_pump_step(webrtc_instance_t* instance, uint64_t now_ms, uint32_t budget)`。
  - 更新 [webrtc.h](/home/qshl/dev/rtc/s2/include/webrtc/webrtc.h)：包含 `webrtc_pump.h`，保持现有 include 兼容。
  - 更新 [webrtc_status.h](/home/qshl/dev/rtc/s2/include/webrtc/webrtc_status.h)：新增 `WEBRTC_STATUS_QUEUE_FULL`（运行时背压语义）。
- 核心实现：
  - 在 `src/core` 新增内部环形事件队列模块（固定容量，`head/tail/size/capacity` + 预分配槽位）。
  - `webrtc_instance` 增加内部事件队列对象。
  - `webrtc_init` 按 `config.event_queue_capacity` 一次性分配队列；`webrtc_deinit` 对称释放。
  - 入队满时立即返回 `WEBRTC_STATUS_QUEUE_FULL`，不覆盖旧事件、不自动扩容。
  - `webrtc_pump_step` 语义固定：
    - `instance == NULL` 返回 `WEBRTC_STATUS_INVALID_ARG`
    - `budget == 0` 返回 `WEBRTC_STATUS_OK`（no-op）
    - 其余情况最多消费 `budget` 个事件；队列空时返回 `WEBRTC_STATUS_OK`
  - 事件队列接口保持内部可见，不新增公共“调试入队”API。
- 测试调整：
  - 新增 `tests/test_event_queue_bounded.c`。
  - 新增 `tests/test_event_queue_backpressure.c`。
  - 更新 `tests/test_smoke.c`：`webrtc_pump_step` 期望从 `NOT_IMPLEMENTED` 改为 `OK`。
  - 更新 `tests/CMakeLists.txt` 注册上述测试目标。

### Test Plan
- 构建与执行：
  - `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`
  - `cmake --build build -j`
  - `ctest --test-dir build -R test_event_queue_bounded --output-on-failure`
  - `ctest --test-dir build -R test_event_queue_backpressure --output-on-failure`
  - `ctest --test-dir build -R test_smoke --output-on-failure`
- 关键断言：
  - 容量为 `N` 时，前 `N` 次入队成功，第 `N+1` 次返回 `WEBRTC_STATUS_QUEUE_FULL`。
  - 队列满后重复入队持续返回 `WEBRTC_STATUS_QUEUE_FULL`，出队后可再次成功入队。
  - `webrtc_pump_step(instance, now_ms, 0)` 返回 `WEBRTC_STATUS_OK`。
  - 空队列调用 `webrtc_pump_step` 返回 `WEBRTC_STATUS_OK`。

### Assumptions
- 本次仅覆盖 `id=21~23`，不提前扩展到 SDP/STUN/ICE 生产事件逻辑。
- 默认验证环境为 Linux/POSIX；RTOS 仅保持可编译边界，不在本轮承诺运行验证。
- 公共 API 保持最小扩展：只新增 `webrtc_pump.h` 与 `WEBRTC_STATUS_QUEUE_FULL`，不引入线程模型变化。
- 参考库对齐原则：保留其“模块化状态码”风格，但不照搬其内部线程/动态队列驱动模型。
