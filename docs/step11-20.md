# ID11-20 实施规格（配置 + PAL + 端口基线）

## Summary
- 目标：一次完成 `docs/plan.md` 的 `id=11~20`，形成“可配置 + 可移植 + 可验证”的基础设施层。
- 采用方案：`方案A 最小闭环`（你已确认）。
- 已锁定决策：
  - `webrtc_init` 直接升级为必传 `config + pal`
  - 错误码采用“模块 BASE + 偏移”
  - PAL 采用显式 vtable，且 `pal` 必须显式传入
  - socket 能力本轮只做 UDP 最小子集
- 参考库对齐：沿用其“分段错误码、配置回填默认值”的方法，但不引入其信令/重平台依赖部分。

## Key Changes
- 公共接口与类型（`id11/12/15/18/20`）
  - 在公开头中新增：
    - `webrtc_config_t` + `webrtc_config_init_default()` + `webrtc_config_validate()`
    - `webrtc_pal_vtable_t`（`mem/time/lock/socket/random` 五类能力）
  - 升级 `webrtc_init` 签名为：
    - `webrtc_status_t webrtc_init(const webrtc_config_t* config, const webrtc_pal_vtable_t* pal, webrtc_instance_t** out_instance);`
  - `webrtc_status.h` 改为模块分段：
    - `GENERAL / CONFIG / SDP / ICE / DTLS / SRTP / RTP / SCTP`
    - 每段定义 `*_BASE` 与最小必要错误码（invalid/config/bounds/not-ready/not-supported/capacity 等）
- 配置实现（`id13/14`）
  - `webrtc_config_init_default(out_cfg)`：写入默认值（带单位）。
  - `webrtc_config_validate(inout_cfg)`：
    - 做边界检查
    - 对允许“0 表示默认”的字段执行回填（参考库 `iceAgentValidateKvsRtcConfig` 风格）
    - 返回 `CONFIG` 分段错误码。
  - `webrtc_init` 内部流程固定：参数检查 -> 复制 config -> validate -> 保存到 instance。
- PAL 与端口（`id16/17/18`）
  - `webrtc_pal_vtable_t` 最小能力集：
    - `mem`: `malloc/calloc/free`
    - `time`: `monotonic_ms`
    - `lock`: `create/destroy/lock/unlock`
    - `socket(UDP)`: `open/bind/sendto/recvfrom/set_nonblocking/close`
    - `random`: `fill`
  - POSIX 端口：提供真实实现。
  - RTOS stub 端口：提供可编译占位实现（返回 `NOT_IMPLEMENTED` 类错误）。
  - 核心层只依赖 PAL，不直接依赖 POSIX 头/符号。
- 构建与文档（`id18/20`）
  - CMake 按 `WEBRTC_PORT_POSIX/WEBRTC_PORT_RTOS` 选择端口编译单元。
  - README 与公共头注释补齐生命周期对称关系：
    - `init/deinit`
    - `create/free`
  - 明确“谁申请谁释放”和 `webrtc_init` 新入参约束。

## Test Plan
- 单元测试新增并纳入 `ctest`：
  - `test_config_defaults`
  - `test_config_validate_bounds`
  - `test_pal_posix_smoke`
  - `test_pal_contract`（时间单调 / 随机基础校验 / UDP loopback 收发）
- 构建与验收命令：
  1. `cmake -S . -B build/base -DWEBRTC_PORT_POSIX=ON -DWEBRTC_PORT_RTOS=OFF`
  2. `cmake --build build/base -j`
  3. `ctest --test-dir build/base --output-on-failure`
  4. `cmake -S . -B build/rtos -DWEBRTC_PORT_POSIX=OFF -DWEBRTC_PORT_RTOS=ON && cmake --build build/rtos -j`
  5. 分层污染扫描：`rg -n "pthread_|poll.h|unistd.h|fcntl.h|sys/" src include`
- 通过标准映射：
  - `id11~15`: 头文件与函数、类型齐全
  - `id16`: POSIX smoke + contract 通过
  - `id17`: RTOS stub 构建通过
  - `id18`: 核心目录无 POSIX 污染
  - `id19`: PAL 合约测试通过
  - `id20`: 生命周期规则文档可检索

## Assumptions
- 本轮不引入信令、编解码、后台线程、重依赖。
- RTOS 本轮仅“可编译占位”，不承诺真机行为。
- socket 范围仅 UDP 最小子集；TCP 不在 `id11~20` 范围内。
- API 破坏性变更（`webrtc_init` 签名升级）已按你的选择执行。
